GOOD TO KNOW

A few details.

Like raw.githack, but the preview happens on your device. No proxy required.

Can I preview a private repository?

Yes. Add a fine-grained GitHub PAT in the options above. Select the repository and grant Contents: Read-only. Classic tokens need the broader repo scope. Organization policies may require approval or SSO authorization. The token is not saved. Refreshing or closing the tab clears it.

What can a preview access?

Repository scripts run in a sandbox without access to Siteview's page, token, or browser storage. They can read other files at the selected commit in the same repository through Siteview's read-only bridge, and send data to external HTTPS services. Only preview code you trust, especially in private repos. Forms, popups, nested frames, and top-level navigation are blocked.

Is this a CDN or production hosting?

No. A static GitHub Pages site cannot change the response headers of GitHub files or act as an authenticated proxy. Share links open the viewer and fetch files on demand. You cannot use them as script or stylesheet URLs on another site. For production hosting, deploy your files to GitHub Pages or a CDN.

Which files and sites work?

Prebuilt HTML, CSS, images, classic scripts, and native ES modules with relative imports. Root-relative paths start at the repository root. Local page links and relative fetch() calls work through the read-only bridge. JSON and text files display as source. Build tools, servers, bare module imports, repository import maps, workers, XHR, and dynamically constructed asset paths are not supported. Build your app first and preview its output directory. No extensionless route fallback is applied.

Are there limits?

Each preview is limited to 200 files, 8 MiB per file, and 40 MiB total. GitHub API limits also apply, typically 60 requests per hour without a token and 5,000 with one. Git LFS is not supported. Large sites may need real hosting.
